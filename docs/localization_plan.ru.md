# План локализации фронтенда OxideRelay

## Цель

Локализовать фронтенд OxideRelay, заменив захардкоженный текст UI на ключи
перевода, загружая переводы из delivery API OxideRelay, используя сам ключ в
качестве запасного варианта, когда перевод отсутствует, и позволяя переключать
язык во время выполнения из UI.

## Требования

1. Заменить текст UI фронтенда на ключи перевода.
2. Если перевод отсутствует, отображать сам ключ.
3. Загружать переводы из delivery endpoint проекта `oxide-relay`.
4. Поддержать настраиваемый base URL сервера локализации, чтобы локальный
   фронтенд мог получать переводы из удалённого экземпляра OxideRelay.
5. Добавить переключатель языка в header сайта и перезагружать переводы при
   переключении.

## Источник переводов

Относительный путь по умолчанию:

```text
/api/v1/projects/oxide-relay/locales/{language}?environment=production
```

Необязательный удалённый источник через runtime config Vite:

```text
VITE_I18N_BASE_URL=http://kpakozz96pyc.xyz:8080
```

Когда задан `VITE_I18N_BASE_URL`, фронтенд должен загружать переводы из:

```text
{VITE_I18N_BASE_URL}/api/v1/projects/oxide-relay/locales/{language}?environment=production
```

## Этапы реализации

### 1. Добавить i18n-инфраструктуру фронтенда

- Создать модуль `i18n` для:
  - состояния текущего языка
  - кэша словарей переводов
  - загрузчика переводов
  - хелпера `t(key)` с запасным вариантом в виде ключа
  - сохранения языка в `localStorage`

### 2. Добавить настраиваемый источник переводов

- Ввести `VITE_I18N_BASE_URL`
- Централизовать построение URL переводов
- Использовать относительные URL, когда переменная не задана
- Использовать абсолютные удалённые URL, когда переменная задана

### 3. Добавить переключение языка во время выполнения

- Добавить переключатель языка в header сайта
- Сохранять выбранный язык
- Перезагружать переводы, когда пользователь переключает язык

### 4. Заменить захардкоженный текст фронтенда на ключи

- Преобразовать общие компоненты layout
- Преобразовать страницу входа
- Преобразовать projects, users, workspace проекта и project panels
- Оставить без изменений текст ошибок, предоставляемый бэкендом, там, где он
  приходит с сервера
- Использовать ключи перевода для запасного/error/loading текста, генерируемого
  фронтендом

### 5. Поведение при загрузке и ошибках

- Не допускать падения приложения, если загрузка переводов завершается ошибкой
- Показывать ключи, когда переводы недоступны или отсутствуют
- Кэшировать загруженные словари по языкам

### 6. Тестирование

- Проверить загрузку языка по умолчанию
- Проверить, что переключение языков обновляет UI
- Проверить построение пути `VITE_I18N_BASE_URL`
- Проверить, что отсутствующие переводы откатываются к ключам
- Проверить, что UI остаётся работоспособным при неудачных запросах переводов

## Примечания

- Текущая кодовая база является источником истины.
- Delivery endpoints являются публичными, но использование удалённого источника
  переводов из локального фронтенда требует, чтобы удалённый экземпляр
  OxideRelay разрешал CORS.
- Изначально поддерживаемые языки фронтенда можно определить статически во
  фронтенде, потому что публичный delivery endpoint не предоставляет публичный
  каталог языков.
